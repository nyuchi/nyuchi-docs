The core directory for Nyuchi tooling. Three kinds of thing live here — **agent
skills** (doctrine an assistant loads), **CLIs** (things you run), and **MCP
servers** (live data an assistant queries) — and each entry says which repo owns
it and how to get it.

<Aside type="note">
  Counts and versions are deliberately absent from the tables below. They drift
  the moment anything ships, so each row links to the live source instead. For
  the Mzizi skill list as the registry currently holds it, call
  `curl -s https://mzizi.dev/api/v1/skills`.
</Aside>

## Agent skills

### `@nyuchi/mzizi-skills` — the published bundle

The design-system and engineering doctrine for the whole ecosystem. Owned by
[`nyuchi/mzizi-tools`](https://github.com/nyuchi/mzizi-tools), authored in git
under `mzizi-skills/skills/<name>/SKILL.md`, published to npm, and projected
into the Mzizi registry so the same bodies serve over HTTP and MCP.

```bash
# every skill, as files in .claude/skills/
npx skills add @nyuchi/mzizi-skills
```

```
# or the whole toolchain as a Claude Code plugin
/plugin marketplace add nyuchi/mzizi-tools
/plugin install mzizi@mzizi-tools
```

### `nyuchi-docs` — repo-local skills

These live in [`nyuchi/nyuchi-docs`](https://github.com/nyuchi/nyuchi-docs)
under `.claude/skills/` and cover working **on this docs site**. They are not
published to npm, so the way to get them is to clone the repo — Claude Code
picks them up automatically when a session runs inside it.

| Skill | Use it when |
| --- | --- |
| `agent-readiness` | Verifying the docs site's agent surfaces after a deploy or Cloudflare change |
| `docs-drift-audit` | Periodic sweep for sidebar orphans, stale strings, and gotchas that no longer hold |
| `kweli-docs-sync` | Kweli shipped something user- or agent-visible and the guides need syncing |
| `mzizi-shell` | Touching the site shell, or replicating it on another Starlight site |
| `release-mcp` | Cutting a new version of the docs MCP stdio bridge |

<Aside type="caution">
  **These five are not distributable today.** Anything reusable outside this
  repo belongs in `@nyuchi/mzizi-skills` instead; anything genuinely specific to
  the docs site is correctly repo-local. `mzizi-shell` is the borderline case —
  it documents a contract another Starlight site would want.
</Aside>

## CLIs

| CLI | Install | Repo | What it does |
| --- | --- | --- | --- |
| `fundi` (`@nyuchi/mzizi-cli`) | `pnpm add -D @nyuchi/mzizi-cli` | [mzizi-tools](https://github.com/nyuchi/mzizi-tools/tree/main/mzizi-cli) | Explores a project, plans a change against the Mzizi registry, applies it on request. SDK and CLI in one package. |
| `nyuchi-docs-mcp` | `npx nyuchi-docs-mcp` | [nyuchi-docs](https://github.com/nyuchi/nyuchi-docs/tree/main/nyuchi-docs-mcp) | stdio bridge to the hosted docs MCP, for clients that want a local process rather than an HTTP endpoint. |

Full instructions for the Mzizi CLI: [mzizi.dev/cli](https://mzizi.dev/cli).

<Aside type="caution">
  **The docs bridge is published unscoped.** `nyuchi-docs-mcp` resolves on npm;
  `@nyuchi/nyuchi-docs-mcp` does not. Every other published tool in the
  ecosystem uses the `@nyuchi` scope, so this one is the odd one out — worth
  reconciling so the naming rule holds everywhere.
</Aside>

### Adding an MCP server to a client

```json
{
  "mcpServers": {
    "mzizi": { "type": "http", "url": "https://mcp.mzizi.dev/mcp" },
    "nyuchi-docs": { "type": "http", "url": "https://docs.nyuchi.com/mcp" }
  }
}
```

### Inspecting one

Use the official inspector rather than hand-rolling JSON-RPC:

```bash
npx @modelcontextprotocol/inspector --web <command-or-url>
```

Note the argument order the launcher wants — **mode flag, then target, then
options** — and that OAuth-gated endpoints answer an unauthenticated
`tools/list` with `401`, so point it at a local stdio bin or a `wrangler dev`
instance instead of production:

```bash
# inside mzizi-tools
pnpm --filter @nyuchi/mzizi-mcp inspect       # web UI over the stdio bin
pnpm --filter @nyuchi/mzizi-mcp inspect:cli   # tools/list as JSON
```

## Adding a tool to this directory

1. Publish it under the `@nyuchi` npm scope with
   `publishConfig.access: "public"`, or document why it stays private.
2. If it's a reusable agent skill, put it in `@nyuchi/mzizi-skills` rather than
   a repo-local `.claude/skills/` — that's what makes it installable.
3. If it's an MCP server, register it (`io.github.nyuchi/<name>`) and give it a
   `server.json` whose version stays in lockstep with `package.json`.
4. Add a row above. Link the source; don't paste a version number.
